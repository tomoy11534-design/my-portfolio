# 要件定義書 — Aide（面接サポートツール）

## 1. 目的・背景
就職・転職の面接を受ける本人が、**準備 → 練習 → 本番 → 振り返り** の一連の流れを1つのツールで回せるようにする。
音声の文字起こしと Claude API による要約・フィードバックで、「話した内容を覚えていない」「逆質問を聞き忘れた」「何が悪かったか分からない」を解消する。

## 2. 利用者・利用環境
| 項目 | 内容 |
|------|------|
| 利用者 | 自分1人（ログイン・認証は不要） |
| 主な端末 | PC（Windows + Google Chrome。オンライン面接と同じPCで横に開いて使う） |
| 面接の形式 | Zoom・Teams・Google Meet 等のオンライン面接（ブラウザ版・デスクトップアプリ版の両方）。ヘッドホン・イヤホン使用とスピーカー使用の両方に対応 |
| 副次的な端末 | iPad（対面面接の後の振り返り・練習用） |
| 通信 | オンライン前提（文字起こし・Claude APIのため） |

## 3. スコープ
### 3.1 対象（In Scope）
- **準備**：応募企業ごとの情報、自分のエピソード（自己PR・ガクチカ等）、想定質問、逆質問リストの登録
- **練習モード**：AIが面接官役で質問し、音声で回答 → 文字起こし → AIが回答をフィードバック
- **本番モード**：面接官の声（PCの再生音）と自分の声（マイク）を分けたリアルタイム文字起こし、逆質問チェックリスト、手書きメモ、AIによる「質問の要点整理」と「関連する登録済みエピソードの提示」
- **振り返り**：面接記録（議事録）の Markdown 出力、AIによる要約・良かった点・改善点の提示
- 上記データのブラウザ（localStorage）への自動保存
- 登録データ全体の JSON エクスポート・インポート（バックアップ・別端末への移行用）

### 3.2 対象外（Out of Scope）
- **本番中にAIが回答文そのものを生成・読み上げ用に提示する機能**（面接官を欺く使い方になり、多くの企業の選考ルールに反するため。本番モードのAIは、自分で登録した内容の参照と要点整理に限定する）
- ログイン・ユーザー管理、複数端末間の自動同期（移行は JSON ファイルによる手動のエクスポート・インポートで行う）
- 面接音声ファイルの保存（テキストのみ保存する）
- Zoom/Teams 等の会議ツールとの直接連携

## 4. 機能要件
### 4.1 準備
| ID | 要件 | 優先度 |
|----|------|--------|
| F-01 | 応募企業を登録・編集・削除できる（企業名、職種、選考段階、面接日時、企業メモ） | 必須 |
| F-02 | 自分のエピソードを登録できる（タイトル、本文、タグ）。全企業で共通利用する | 必須 |
| F-03 | 企業ごとに想定質問と、それに使うエピソードの紐づけを登録できる | 任意 |
| F-04 | 企業ごとに逆質問リストを登録できる | 必須 |

### 4.2 練習モード
| ID | 要件 | 優先度 |
|----|------|--------|
| F-11 | 企業・職種・選考段階をもとに、AIが面接官役として質問を1問ずつ出す | 必須 |
| F-12 | 回答はマイク入力で行い、リアルタイムに文字起こしを表示する。テキスト入力でも回答できる | 必須 |
| F-13 | 回答ごとに、AIが「結論の明確さ・具体性・質問との一致・長さ」の観点でフィードバックする | 必須 |
| F-14 | AIは直前の回答内容を踏まえた深掘り質問をすることができる | 任意 |

### 4.3 本番モード
| ID | 要件 | 優先度 |
|----|------|--------|
| F-21 | 開始・一時停止・終了ボタンで文字起こしを制御し、発言をタイムスタンプ付きで表示する | 必須 |
| F-21a | 開始時に音声の取り込み方法を選べる。「ヘッドホン・イヤホン」：面接官の声はPCの再生音から、自分の声はマイクから取り込む／「スピーカー」：マイクのみで両者の声を取り込む | 必須 |
| F-21b | 「ヘッドホン・イヤホン」選択時は、画面共有ダイアログで面接のタブ（ブラウザ版）または画面全体＋システム音声（Zoom等のアプリ版）を選ばせる。手順を画面上で案内する | 必須 |
| F-21c | 発言には話者（面接官／自分）を表示する。「ヘッドホン・イヤホン」では取り込み元で自動判定し、「スピーカー」では話者を区別しない | 必須 |
| F-21d | 再生音・マイクのそれぞれに音量メーターを表示し、音声が取り込めていない場合は警告する | 必須 |
| F-21e | 途中でヘッドホンを外した等の場合に、面接を止めずに取り込み方法を切り替えられる | 任意 |
| F-22 | 逆質問リストをチェックリスト表示し、手動でチェックできる | 必須 |
| F-23 | 文字起こし中に逆質問の内容が話題に出た場合、「回答済みかも」の候補表示をする（チェックは手動で確定） | 任意 |
| F-24 | 自由記述のメモ欄を置く（面接官の名前、気になった点など） | 必須 |
| F-25 | 直近の発言からAIが「いま聞かれている質問」を1行に要約して表示する | 必須 |
| F-26 | 聞かれた質問に関連する、自分が登録済みのエピソードのタイトルを最大3件提示する（本文の自動生成はしない） | 必須 |
| F-27 | 画面は目線移動が少ないよう、スクロールなしで1画面に収める（詳細は 4.3.1） | 必須 |

#### 4.3.1 本番モードの画面（緊張していても一目で分かること）
面接中は緊張で視野が狭くなり、細かい文字を読む余裕がない前提で設計する。「読む」のではなく「チラ見で分かる」ことを最優先とする。

**情報の優先順位とレイアウト**
| ID | 要件 | 優先度 |
|----|------|--------|
| F-28a | 画面を上から「① いま聞かれている質問 → ② 関連エピソード → ③ 逆質問チェックリスト・メモ → ④ 文字起こし」の優先順に配置し、①を最も大きく目立たせる | 必須 |
| F-28b | Zoom 等の横に並べて使う前提で、画面幅の半分（幅960px × 高さ900px程度）でスクロールなしに収まること。幅640px程度まで狭めた場合は④を折りたたむ | 必須 |
| F-28c | 文字起こし（④）は補助情報とし、直近の数発言だけを小さめに表示する。過去分は折りたたみ、読みに行かなくても困らない作りにする | 必須 |
| F-28d | ①が新しい質問に切り替わったときは、0.5秒ほど控えめに強調（背景色をふわっと変える等）して気づけるようにする。点滅や大きな動きは使わない | 必須 |
| F-28e | 録音中・一時停止中・音声が取れていない等の状態は、画面上部の1行にアイコン＋色＋文字で常時表示する | 必須 |

**文字とボタンの大きさ**
| ID | 要件 | 優先度 |
|----|------|--------|
| F-29a | 文字サイズの目安：① 質問要約 28px以上・太字／② エピソード名 20px以上／③ チェックリスト・メモ 18px以上／④ 文字起こし 16px以上 | 必須 |
| F-29b | 文字サイズを「標準・大・特大」の3段階で切り替えられ、設定は保存される | 必須 |
| F-29c | ボタン・チェックボックスのタップ領域は48px以上とし、隣のボタンとは8px以上離す | 必須 |
| F-29d | 「終了」は誤操作防止のため、他のボタンから離して配置し、確認を挟む（または長押しで終了） | 必須 |
| F-29e | 一時停止／再開・メモ欄へ移動・逆質問のチェックをキーボードショートカットでも操作できる（メモ入力と衝突しないよう修飾キー付き） | 任意 |

**色とダークモード**
| ID | 要件 | 優先度 |
|----|------|--------|
| F-30a | ライト／ダークの2テーマを用意する。初期値は OS の設定に従い、手動でも切り替えられる（設定は保存） | 必須 |
| F-30b | 文字と背景のコントラスト比は、本文 4.5:1 以上、①の質問要約は 7:1 以上を確保する | 必須 |
| F-30c | ダークモードは真っ黒・真っ白を避け（例：背景は濃いグレー、文字はやや抑えた白）、長時間見ても目が疲れない配色にする | 必須 |
| F-30d | 状態や話者を色だけで区別しない（「面接官」「自分」のラベル、アイコンを併用する） | 必須 |
| F-30e | 使うアクセントカラーは1〜2色に絞り、画面がにぎやかにならないようにする | 必須 |

**面接を邪魔しない**
| ID | 要件 | 優先度 |
|----|------|--------|
| F-30f | 面接中はダイアログ（モーダル）・効果音・ブラウザ通知を出さない。エラーは画面上部の状態表示に小さく出す | 必須 |
| F-30g | AIの応答待ちでレイアウトがガタつかないよう、各エリアの大きさは固定し、待機中は控えめな表示にとどめる | 必須 |

### 4.4 振り返り
| ID | 要件 | 優先度 |
|----|------|--------|
| F-31 | 面接終了後、文字起こし・メモ・チェックリストの結果を1件の「面接記録」として保存する | 必須 |
| F-32 | AIが面接記録から「聞かれた質問一覧・自分の回答の要約・良かった点・改善点・次回までの宿題」をまとめる | 必須 |
| F-33 | 面接記録を Markdown でダウンロード・クリップボードコピーできる | 必須 |
| F-34 | 企業ごとに過去の面接記録を一覧・閲覧できる | 必須 |

### 4.5 データ管理
| ID | 要件 | 優先度 |
|----|------|--------|
| F-41 | 登録データ全体（企業、エピソード、想定質問、逆質問、面接記録、アプリ設定）を1つの JSON ファイルとしてダウンロードできる | 必須 |
| F-42 | ファイル名は `aide-backup-YYYYMMDD-HHmm.json` とする | 必須 |
| F-43 | JSON にはデータ形式のバージョン番号とエクスポート日時を含める | 必須 |
| F-44 | JSON ファイルを選択してインポートできる。読み込み前に、件数（企業◯件・エピソード◯件・面接記録◯件）とエクスポート日時をプレビュー表示する | 必須 |
| F-45 | インポート方法を「上書き（今のデータをすべて置き換える）」と「追加（今のデータに足す）」から選べる | 必須 |
| F-46 | 「上書き」は確認画面を挟み、実行直前に現在のデータを自動でエクスポート（ダウンロード）してから置き換える | 必須 |
| F-47 | 「追加」で同じIDのデータがある場合は、更新日時が新しい方を残す | 必須 |
| F-48 | JSON の形式が不正・必須項目の欠落・未対応のバージョンの場合は、何も変更せずにエラー内容を表示する | 必須 |
| F-49 | 古いバージョンの JSON は、現在の形式に変換してから読み込む | 任意 |

## 5. 非機能要件
| 区分 | 要件 |
|------|------|
| 技術（フロント） | Vue.js 3（Composition API / `<script setup>`）、Vite |
| 技術（サーバー） | Node.js + Express の小さな中継サーバー。Claude API キーをブラウザに出さないために使う |
| 文字起こし（自分の声） | ブラウザの Web Speech API（日本語・連続認識）。無料。Chrome 前提 |
| 文字起こし（面接官の声） | `getDisplayMedia` で取得した再生音を中継サーバー経由で外部のストリーミング音声認識APIへ送る（サービスは仕様策定時に決定。下記参照） |
| 音声の取り扱い | 音声はリアルタイム変換のみに使い、サーバー・ブラウザのどちらにも保存しない |
| AI | Claude API（既定は `claude-opus-5`）。本番モードは思考の深さ（effort）を low にして応答速度を優先し、振り返り・練習フィードバックは medium〜high で精度を優先する。モデルは `.env` で用途別に変更できる |
| 応答速度 | 本番モードの質問要約は、発言の区切りから3秒以内の表示を目標とする |
| データ保存 | localStorage のみ。キーは `aide:` を接頭辞とする。各データにID（UUID）と作成日時・更新日時を持たせる（インポート時の統合に使う） |
| 容量 | localStorage は約5MBが上限のため、使用量を設定画面に表示し、80%を超えたら古い面接記録のエクスポート・削除を促す |
| プライバシー | APIキー（Claude・音声認識）はサーバーの環境変数（`.env`、Git管理外）で管理。Claude にはテキストのみを送る |
| デザイン | 落ち着いた配色で、ライト／ダーク両対応。本番モードは 4.3.1 の基準に従う |
| 動作の軽さ | Zoom 等と同時に動かすため、本番モードは重いアニメーション・装飾（ぼかし効果等）を使わない。文字起こしは表示する発言数を制限し、長時間の面接でも動作が重くならないようにする |
| 応答性 | ボタン操作への反応は0.1秒以内。AIの応答待ちの間も画面操作（チェック・メモ入力）は止めない |
| コーディング規約 | ファイル名は小文字ケバブケース、コメントは日本語 |

## 6. 前提・制約・未決事項
- **面接官の声の取り込み（決定）**：ヘッドホン・イヤホン使用時はマイクに面接官の声が入らないため、画面共有（`getDisplayMedia`）で再生音を取得して文字起こしする。Web Speech API は MediaStream を入力にできないため、再生音側は外部の音声認識APIを使う。
  - ブラウザ版の面接（Meet・Zoom Web 等）：「Chromeタブ」を共有し「タブの音声も共有」をON
  - アプリ版の面接（Zoom・Teams デスクトップ）：「画面全体」を共有し「システム音声も共有」をON（Windows の Chrome で対応。Mac は OS・Chrome のバージョンに依存するため対象外とする）
  - 画面全体のシステム音声には通知音など他の音も混ざるため、面接中は他アプリの音を切る運用とする
  - 共有した映像は使わず、音声トラックのみ利用する
- **音声認識APIの選定（暫定決定）**：日本語のストリーミング認識ができることが条件。実装の簡単さから Deepgram（モデル `nova-2`、`.env` の `DEEPGRAM_MODEL` で変更可）を採用した。中継処理は `server/stt-relay.js` にまとめてあり、精度・料金に不満があれば OpenAI（Realtime API の文字起こし）や Google Cloud Speech-to-Text に差し替える。
- **音声認識の料金**：面接官の声の分だけ従量課金が発生する（1面接あたり30〜60分を想定）。練習モードは自分の声のみなので Web Speech API で無料。
- **スピーカー使用時**：マイクで両者の声を拾うため、話者の区別はしない。エコーキャンセルはブラウザ標準の機能に任せる。
- **本番利用のルール**：本番モードは、メモ参照が許されている面接で使うこと。録音・文字起こしの可否を企業から指定されている場合はそれに従う。
- Claude API の利用料金が発生する。本番モードは発言の区切りごとに呼ぶため、呼び出し回数の上限（例：1面接あたり100回）を設ける。
- ホスティングは当面ローカル実行（`npm run dev`）とし、公開は未定。
- **エクスポートファイルの扱い**：JSON には面接の文字起こしや個人のエピソードが暗号化なしで入る。クラウドストレージ等に置く場合は自己責任で管理する（APIキーはサーバー側にあるため JSON には含まれない）。
